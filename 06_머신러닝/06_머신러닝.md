# 🤖 머신러닝 분석 정리

> 로지스틱 회귀를 통해 국가별 제품 속성 효과의 통계적 차이를 확인한 이후,
머신러닝에서는 동일한 변수들이 실제 소비자의 **만족·불만족을 얼마나 잘 구분할 수 있는지**와
각 변수가 예측에 얼마나 기여하는지를 추가적으로 검증하였다.
> 

---

# 1. 🎯 머신러닝 분석 목적

앞선 로지스틱 회귀에서는

> **“어떤 속성이 만족도와 통계적으로 관련되어 있으며, 그 효과가 국가별로 다른가?”**
> 

를 검증하였다.

머신러닝에서는 여기서 한 단계 더 나아가,

> **“이러한 정보를 이용했을 때 실제 만족·불만족 리뷰를 얼마나 잘 구분할 수 있는가?”**
> 

를 확인하였다.

또한 최종 모델의 Feature Importance와 SHAP을 이용하여

> **“모델이 만족·불만족을 구분할 때 실제로 어떤 정보를 중요하게 활용하는가?”**
> 

를 추가적으로 확인하였다.

따라서 통계 분석과 머신러닝 분석의 역할은 다음과 같이 구분하였다.

| 분석 | 주요 목적 |
| --- | --- |
| 로지스틱 회귀 | 변수의 통계적 효과와 국가별 차이 검증 |
| 머신러닝 | 예측 성능과 변수의 예측 기여도 확인 |

---

# 2. 📂 머신러닝 입력 변수 구성

머신러닝의 종속변수는 로지스틱 회귀와 동일하게 `Y`를 사용하였다.

```
Y = 0 : 불만족 리뷰
Y = 1 : 만족 리뷰
```

설명변수에는 다음 정보를 활용하였다.

## 2.1 기본 속성 9개

- 보습
- 향
- 발림성
- 자극
- 용기
- 배송
- 기능
- 가격
- 브랜드충성도

## 2.2 국가 × 속성 상호작용 27개

로지스틱 회귀에서 확인한 국가별 속성 차이를 머신러닝에서도 반영하기 위해

```
국가 3개 × 속성 9개 = 27개
```

상호작용 변수를 유지하였다.

## 2.3 제품_ID

머신러닝에서는 제품별 고유한 차이를 통제하기 위해

```
국가 + 제품순위
```

를 결합한 `제품_ID`를 추가하였다.

예:

```
KR_P01
US_P03
JP_P07
RU_P02
```

`제품_ID`는 제품의 순위를 수치형 변수로 해석하기 위한 것이 아니라,

> **제품마다 존재할 수 있는 고유한 만족도 차이를 통제하기 위한 명목형 변수**
> 

로 사용하였다.

따라서 모델 내부에서는 필요에 따라 One-Hot Encoding을 적용하지만,

분석상 의미는 하나의 **제품 통제 변수**이다.

---

# 3. ❌ 머신러닝에서 제외한 변수

## 3.1 리뷰_번호

`리뷰_번호`는 각 행을 구분하기 위한 식별자이므로 예측 정보로 사용하지 않았다.

---

## 3.2 별점

종속변수 `Y` 자체가 별점을 기준으로 생성되었다.

```
1·2점 → Y = 0
4·5점 → Y = 1
```

따라서 별점을 설명변수로 포함하면 정답 정보를 모델에 직접 제공하는

**Data Leakage**가 발생하므로 제외하였다.

---

## 3.3 제품_순위

`제품_순위`는 EDA에서 만족도와 유의한 관계가 확인되었지만,

- 효과크기가 작았으며
- 순위 증가에 따른 일관된 만족도 변화가 없었고
- 동일한 순위가 국가별로 서로 다른 제품을 의미하였다.

따라서 `1~10`의 연속적·순서형 효과로 해석하지 않았다.

대신 머신러닝에서는 제품 자체를 구분하기 위해

`국가 + 제품순위`를 결합한 `제품_ID`를 사용하였다.

# 4. ✂️ Train / Test 데이터 분할

전체 6,756건을

```
Train : 70% = 4,729건
Test  : 30% = 2,027건
```

으로 분할하였다.

종속변수의 만족·불만족 비율을 유지하기 위해

Stratified 방식으로 분할하였다.

실제 분할 후 만족(1) 비율은

- Train: **65.4%**
- Test: **65.4%**

로 거의 동일하게 유지되었다.

메인 머신러닝 분석의 Test 데이터는

> **분석 대상 40개 제품군 내에서 새로운 리뷰가 들어왔을 때의 일반화 성능**
> 

을 평가하는 목적으로 사용하였다.

# 5. 🔒 Test-set 오염 방지

머신러닝 모델을 선택하는 과정에서 Test 성능을 반복적으로 확인하면

> **Test 데이터에 맞춰 모델을 선택하는 문제**
> 

가 발생할 수 있다.

이를 방지하기 위해 모델 선택과 하이퍼파라미터 튜닝은 모두

**Train 데이터 내부에서만 수행**하였다.

전체 구조는 다음과 같다.

```
전체 데이터
↓
Train 70% / Test 30%
↓
Train 내부 5-Fold CV
↓
모델 비교
↓
하이퍼파라미터 튜닝
↓
최종 모델 선택
↓
과적합 여부 확인
↓
모든 설정 확정
↓
최종 XGBoost의 Test 성능 평가
```

즉,

> **Test 결과를 보고 모델을 다시 선택하거나 하이퍼파라미터를 수정하지 않았다.**
> 

또한 모든 리뷰를 만족(1)로 예측하는 기준선은 모델 선택용이 아니라
최종 Test 성능을 해석하기 위한 **고정 비교 기준**으로만 사용하였다.

# 6. 🔄 Cross Validation 사용 이유

한 번의 Train/Validation 분할 결과만으로 모델을 선택하면

어떤 데이터가 Validation에 포함되었는지에 따라 결과가 달라질 수 있다.

따라서 Train 데이터 내부에서 **5-Fold Cross Validation**을 적용하였다.

```
Train
↓
5개 Fold로 분할
↓
4개 Fold 학습 + 1개 Fold 검증
↓
검증 Fold를 바꾸어 총 5회 반복
↓
평균 성능 계산
```

이를 통해 우연히 특정 Validation 데이터에서만 높은 성능을 보이는 모델보다

> **여러 데이터 분할에서도 상대적으로 안정적인 모델**
> 

을 선택하고자 하였다.

# 8. 📏 주 평가 지표 — F1 Score

종속변수의 만족·불만족 비율이 완전히 동일하지 않기 때문에
Accuracy만으로 모델을 선택하지 않았다.

주 평가 지표는 **F1 Score**로 설정하였다.

본 이진 분류에서 기본 F1은 만족(1)을 양성 클래스로 두고
Precision과 Recall을 함께 반영한다.

따라서 모델 선택은 Train 내부 CV의 **평균 F1**을 기준으로 수행하였으며,
ROC-AUC와 Accuracy를 보조적으로 확인하였다.

다만 만족(1)이 다수 클래스이므로 양성 클래스 F1만으로
만족·불만족 양쪽 성능을 모두 설명할 수는 없다.

따라서 최종 Test 해석에서는

- F1(만족)
- F1(불만족)
- Macro-F1
- MCC

를 함께 확인하여 한쪽 클래스에 치우친 해석을 피하였다.

# 9. 🔧 하이퍼파라미터 튜닝

각 머신러닝 알고리즘은 내부 설정에 따라 성능이 달라질 수 있다.

따라서 미리 정의한 후보 범위 내에서 GridSearchCV를 이용해
Train 내부에서 하이퍼파라미터를 탐색하였다.

중요한 점은,

> **하이퍼파라미터 선택 역시 Test 데이터가 아니라 Train 내부 CV 결과만 이용했다는 것**
> 

이다.

또한 결과를 확인한 후 유리한 모델만 추가하는 방식을 피하기 위해
최종 튜닝 대상 모델 후보는 8개로 고정하였다.

튜닝 결과 상위 모델은 다음과 같았다.

| CatBoost | 0.8251 | 0.0129 | 0.8085 | 0.7617 |
| **XGBoost** | **0.8238** | **0.0087** | **0.8141** | **0.7602** |

CatBoost와 XGBoost의 CV F1 차이는 약 **0.0013**으로 매우 작게 나타났다.

# 10. 🏆 최종 모델 선택

Train 내부 Cross Validation 결과를 기준으로 최종 모델을 선정하였다.

튜닝 결과에서 CatBoost의 CV F1이 0.8251로 가장 높았지만,
XGBoost의 CV F1은 0.8238로 차이가 약 **0.0013**에 불과하였다.

또한 XGBoost는

- CV ROC-AUC: **0.8141**로 CatBoost(0.8085)보다 높았고
- CV F1 표준편차: **0.0087**로 CatBoost(0.0129)보다 작았으며
- 실제 실행 환경에서 CatBoost보다 학습·튜닝 부담이 낮았다.

따라서 미세한 F1 차이만으로 CatBoost를 우선하지 않고,
**유사한 예측 성능에서 ROC-AUC, fold 간 변동성, 계산 효율성을 함께 고려하여
CatBoost를 최종 선택 대상에서 제외**하였다.

CatBoost 제외 후 Train 내부 5-Fold CV 평균 F1이 가장 높은 모델은
XGBoost였다.

> **최종 모델 = XGBoost**
> 

최종 XGBoost의 CV 성능과 하이퍼파라미터는 다음과 같다.

| 항목 | 값 |
| --- | --- |
| CV F1 | **0.8238** |
| CV F1 STD | **0.0087** |
| CV ROC-AUC | **0.8141** |
| CV Accuracy | **0.7602** |
| learning_rate | **0.03** |
| max_depth | **5** |
| n_estimators | **300** |
| subsample | **0.8** |

이 과정에서는 최종 XGBoost의 Test 성능을 모델 선택 기준으로 사용하지 않았다.

# 11. 🧪 최종 Test 평가

모델과 하이퍼파라미터를 모두 확정한 이후,
최종 XGBoost의 일반화 성능을 Test 데이터에서 평가하였다.

또한 Test 데이터에서 만족 리뷰가 약 **65.4%**를 차지하므로,
모델의 성능이 단순히 다수 클래스의 영향으로 높게 나타난 것은 아닌지 확인하기 위해
**모든 리뷰를 만족(1)으로 예측하는 기준선(Baseline)**과 비교하였다.

| 모델 | Accuracy | F1(만족) | F1(불만족) | Macro-F1 | MCC |
| --- | --- | --- | --- | --- | --- |
| 전부 만족 예측 기준선 | 0.654 | 0.791 | 0.000 | 0.395 | 0.000 |
| **최종 XGBoost** | **0.753** | **0.819** | **0.614** | **0.716** | **0.438** |

전부 만족으로 예측한 기준선은 Accuracy가 0.654, F1(만족)이 0.791로
비교적 높게 나타났지만, 불만족 리뷰를 전혀 구분하지 못해
**F1(불만족)=0, MCC=0**으로 나타났다.

반면 최종 XGBoost는 **Accuracy 0.753, Macro-F1 0.716, MCC 0.438**로
기준선보다 높은 성능을 보였으며,
만족뿐 아니라 불만족 리뷰도 일정 수준 구분하는 것으로 확인되었다.

최종 XGBoost의 추가 Test 지표는 다음과 같다.

- Precision(만족): **0.788**
- Recall(만족): **0.851**
- ROC-AUC: **0.813**
- PR-AUC: **0.894**
- LogLoss: **0.491**

특히 만족 클래스를 기준으로 한 F1만 사용할 경우 다수 클래스의 영향을 받을 수 있으므로,
본 분석에서는 **만족·불만족 클래스를 동일한 비중으로 평가하는 Macro-F1과
전체 분류 결과를 함께 반영하는 MCC를 병행 확인**하였다.

이 성능은

> **분석 대상 40개 제품군 내에서 새로운 리뷰가 들어왔을 때 만족·불만족을 구분하는 성능**
> 

으로 해석한다.

따라서 본 결과를

> **“학습에서 한 번도 보지 못한 새로운 제품에서도 동일한 수준의 성능을 보인다”**
> 

고 해석하지 않으며, 신제품에 대한 일반화 가능성은 별도의
**제품 단위 Group Holdout 검증**을 통해 보조적으로 확인한다.

# 12. 📊 과적합 여부 확인

최종 모델은 단순히 Test 점수만 확인하지 않고

```
Train 성능
vs
Train 내부 CV 성능
```

을 함께 비교하였다.

실제 결과는 다음과 같다.

| Metric | Train | CV | Train-CV Gap |
| --- | --- | --- | --- |
| F1 | 0.8413 | 0.8238 | 0.0175 |
| ROC-AUC | 0.8598 | 0.8141 | 0.0458 |
| Accuracy | 0.7846 | 0.7602 | 0.0244 |

Train 성능이 CV보다 높게 나타났지만,
F1 기준 차이는 약 **0.018**, Accuracy 기준 약 **0.024**였다.

따라서 Train 성능과 CV 성능 사이에 차이는 존재하지만,
현재 결과만으로 심한 과적합이라고 보기는 어렵다.

이 진단 역시 Test set을 사용하지 않고 Train 내부에서 수행하였다.

# 13. 🔎 Feature Importance

최종 모델에서 각 변수가 예측에 얼마나 많이 활용되었는지 확인하기 위해
Feature Importance를 산출하였다.

XGBoost의 gain 기반 중요도를 사용하였으며,
One-Hot Encoding 후 76개로 변환된 피처를
원본 37개 변수 단위로 다시 합산하였다.

상위 중요도는 다음과 같이 나타났다.

| 변수 | Importance Ratio |
| --- | --- |
| `제품_ID` | **39.37%** |
| `국가_일본_x_자극` | 4.97% |
| `자극` | 4.22% |
| `국가_러시아_x_발림성` | 4.11% |
| `국가_러시아_x_자극` | 3.86% |
| `국가_일본_x_보습` | 3.72% |
| `국가_러시아_x_향` | 3.43% |
| `국가_미국_x_자극` | 3.36% |

누적 중요도 90%에 도달하기까지 **22개 원본 변수**가 포함되었다.

Feature Importance는

> **모델이 예측 과정에서 어떤 변수를 상대적으로 많이 활용했는가**
> 

를 확인하기 위한 지표이다.

다만 Feature Importance는

- 통계적 유의성 검정이 아니며
- 인과관계를 의미하지 않는다.

또한 누적 중요도 90% 변수 목록은 설명을 위한 참고 결과이며,
이를 이용해 변수를 제거하거나 모델을 다시 선택·튜닝하지 않았다.

# 14. 🧠 SHAP 분석

최종 XGBoost 모델의 예측 구조를 보다 구체적으로 해석하기 위해
SHAP 분석을 수행하였다.

SHAP은 각각의 리뷰에 대해

> **각 변수가 모델의 예측값을 어느 방향으로 얼마나 변화시켰는가**
> 

를 확인할 수 있다.

이를 통해 단순한 변수 중요도뿐 아니라

- 어떤 변수가 만족 예측을 높이는지
- 어떤 변수가 불만족 예측을 높이는지
- 특정 변수의 영향이 관측치별로 어떻게 달라지는지

를 추가적으로 확인하였다.

실행 환경의 Windows Application Control 정책으로 인해
Python `shap` 패키지의 의존 라이브러리인 `llvmlite.dll` 로드가 차단되었으므로,
최종 XGBoost 모델의 **Native TreeSHAP** 기능을 사용하였다.

구체적으로 XGBoost `Booster.predict()`의

- `pred_contribs=True` → TreeSHAP 기여도
- `pred_interactions=True` → TreeSHAP interaction

을 이용하였다.

SHAP 값의 합과 XGBoost의 output margin이 일치하는지 검증한 결과
최대 오차는 **2.62×10⁻⁶**으로 나타나,
계산된 SHAP 기여도의 additivity가 정상적으로 확인되었다.

SHAP 계산에는 Test 데이터 중 **200건**을 표본으로 사용하였다.

# 15. 🔗 제품_ID SHAP 통합

`제품_ID`는 명목형 변수이기 때문에
XGBoost에 입력되는 과정에서 여러 One-Hot 변수로 변환된다.

예:

```
제품_ID_KR_P01
제품_ID_KR_P02
제품_ID_US_P01
제품_ID_JP_P07
...
```

이를 그대로 SHAP 결과에 표시할 경우
제품 ID가 수십 개 변수로 나뉘어 나타나
다른 제품 속성의 중요도를 확인하기 어려워진다.

따라서 SHAP 결과에서는 모든 `제품_ID_*` SHAP 값을
원본 변수인 `제품_ID` 하나로 다시 통합하였다.

통합 시 단순히 각 더미의 평균 절대 SHAP 값을 더하지 않고,

```
각 리뷰별 제품_ID 더미 SHAP 합산
↓
합산값의 절대값 계산
↓
전체 리뷰 평균
```

순서로 계산하였다.

원본 변수 단위로 통합한 Global SHAP 상위 결과는 다음과 같다.

| 변수 | mean(|SHAP|) | 비중 |
| --- | ---: | ---: |
| `자극` | **0.5111** | **20.80%** |
| `제품_ID` | **0.3951** | **16.08%** |
| `기능` | **0.2839** | **11.55%** |
| `보습` | 0.1862 | 7.58% |
| `배송` | 0.1123 | 4.57% |
| `국가_일본_x_보습` | 0.1070 | 4.36% |
| `국가_러시아_x_향` | 0.1069 | 4.35% |
| `국가_미국_x_보습` | 0.0884 | 3.60% |
| `국가_러시아_x_발림성` | 0.0774 | 3.15% |
| `발림성` | 0.0761 | 3.10% |

누적 SHAP 중요도 90%에 도달하기까지 **17개 원본 변수**가 포함되었다.

이를 통해 모델 내부에서는 제품별 정보를 정상적으로 활용하면서도
최종 해석에서는 `제품_ID`라는 하나의 통제 변수로 표현하였다.

단, `제품_ID`는 여러 제품 범주를 통합한 명목형 변수이므로
하나의 증가·감소 방향으로 해석하지 않는다.

# 16. ⚠️ SHAP 해석 원칙

SHAP 결과는

> **모델의 예측 기여도**
> 

를 설명한다.

따라서

```
SHAP이 높다
≠
통계적으로 유의하다
≠
원인이다
```

로 해석하지 않는다.

로지스틱 회귀의 p-value와 Odds Ratio가 통계적 관계를 설명한다면,
SHAP은 최종 머신러닝 모델이 실제 예측에서 어떤 정보를 활용했는지를 보여준다.

또한 `제품_ID`는 명목형 통제 변수이므로
Global SHAP 중요도에는 포함하되 방향 해석에서는 제외하였다.

방향 해석은 제품 더미를 제외한 Beeswarm과 Dependence Plot을 이용하였다.
Native TreeSHAP interaction 기준으로 주요 상호작용 중에서는

- `자극` ↔ `기능`: **0.0790**
- `보습` ↔ `자극`: **0.0330**
- `배송` ↔ `자극`: **0.0291**
- `국가_러시아_x_향` ↔ `자극`: **0.0378**
- `발림성` ↔ `기능`: **0.0196**

등이 상대적으로 크게 나타났다.

이는 모델 내부의 예측 상호작용 강도이며,
통계적 상호작용의 유의성 검정값으로 해석하지 않는다.

또한 SHAP은 Test 데이터 200건 표본으로 계산하였으므로
세부 중요도 순위와 개별 패턴에는 표본 변동 가능성이 존재한다.

Local SHAP의 기여도 합은 XGBoost의 **margin(log-odds) 스케일**에서 해석한다.

# 17. 🔍 제품 단위 Group Holdout 추가 검증

메인 분석은 리뷰 단위로 Train/Test를 분할하였기 때문에

동일 제품의 서로 다른 리뷰가 Train과 Test에 함께 포함될 수 있다.

이는 메인 연구목적인

> **선정된 40개 제품군 내에서 소비자 만족·불만족 요인을 분석**
> 

하는 데에는 적합하지만,

> **학습에 포함되지 않은 완전히 새로운 제품**
> 

에 대한 성능을 의미하지는 않는다.

따라서 신제품 수준의 일반화 가능성을 별도로 확인하기 위해

제품 단위 Group Holdout 검증을 추가하였다.

---

# 18. 🧩 Group Holdout에서 제품_ID를 제외한 이유

Group Holdout에서는 `제품_ID`를

> Train과 Test를 나누는 **Group 기준**
> 

으로만 사용하였다.

신제품 Test에 포함된 제품은 Train에서 한 번도 등장하지 않으므로

제품 자체의 ID를 예측 정보로 사용하는 것은

신제품 일반화 검증의 목적과 맞지 않는다.

따라서 Group 검증에서는

```
제품_ID
→ Group 분할 기준으로 사용
→ 예측변수에서는 제외
```

하였다.

대신 국가 정보가 완전히 사라지지 않도록

한국을 기준으로 한 국가 더미를 포함하였다.

---

# 19. 🔁 메인 모델과 동일한 XGBoost 사용

초기 Group 검증에서는 여러 알고리즘을 다시 비교할 경우

```
메인 분석 = XGBoost
Group 검증 = 다른 알고리즘
```

처럼 모델 자체가 달라질 가능성이 있었다.

이 경우 성능 차이가

- 데이터 분할 방식 때문인지
- 제품_ID 제거 때문인지
- 알고리즘 변경 때문인지

명확하게 구분하기 어렵다.

따라서 최종 Group 검증에서는

> **메인 분석에서 선정된 XGBoost와 동일한 하이퍼파라미터를 그대로 사용**
> 

하였다.

즉 Group Holdout은 새로운 최종 모델을 선정하기 위한 분석이 아니라

> **이미 선택된 메인 모델 구조가 처음 보는 제품에서도 어느 정도 유지되는지를 확인하기 위한 보조 검증**
> 

으로 수행하였다.

---

# 20. 🔄 반복 Product Group Holdout

전체 제품은 40개이므로
Group Holdout을 한 번만 수행하면
어떤 제품이 Test에 포함되는지에 따라 결과가 크게 달라질 수 있다.

따라서 단일 분할 결과에 의존하지 않고
제품 단위 GroupShuffleSplit을 **20회 반복**하였다.

각 반복에서 제품의 30%를 Test group으로 두어

- Train 제품: **28개**
- Test 제품: **12개**
- Train/Test 제품 중복: **0개**

가 되도록 분할하였다.

각 반복에서

```
제품 단위 Train/Test 분리
↓
Train/Test 제품 중복 = 0 확인
↓
Train 제품으로 동일 XGBoost 학습
↓
학습에서 보지 못한 Test 제품 평가
↓
성능 저장
```

과정을 수행하였다.

20회 반복 결과는 다음과 같다.

| 지표 | 평균 | 표준편차 | 최솟값 | 최댓값 |
| --- | --- | --- | --- | --- |
| Accuracy | 0.724 | 0.032 | 0.675 | 0.783 |
| Precision | 0.763 | 0.042 | 0.709 | 0.854 |
| Recall | 0.828 | 0.034 | 0.776 | 0.896 |
| F1 | **0.794** | **0.035** | 0.741 | 0.856 |
| MCC | **0.370** | **0.040** | 0.302 | 0.448 |
| ROC-AUC | **0.767** | **0.025** | 0.719 | 0.813 |

즉 처음 보는 제품을 대상으로 한 반복 검증에서도
F1은 평균 0.794, MCC는 평균 0.370으로 나타났다.

다만 이 결과는 메인 Test와 입력 변수 구성이 다르므로
두 점수를 단순히 우열 비교하지 않는다.

# 21. 📏 Group Holdout 평가 지표

Group Holdout에서는 F1 하나만으로 성능을 판단하지 않았다.

함께 확인한 주요 지표는

- Accuracy
- Precision
- Recall
- F1
- MCC
- ROC-AUC

이다.

특히 MCC는

> **True Positive, True Negative, False Positive, False Negative를 모두 반영하는 지표**
> 

이므로 클래스 비율이 완전히 균등하지 않은 상황에서

F1과 함께 일반화 성능을 판단하는 보조 지표로 활용하였다.

---

# 22. ⚠️ 메인 Test와 Group Holdout의 해석 차이

두 결과는 같은 의미의 Test가 아니다.

| 구분 | 메인 Test | Group Holdout |
| --- | --- | --- |
| 분할 단위 | 리뷰 | 제품 |
| 제품_ID | 예측변수로 포함 | 예측변수에서 제외 |
| 국가 더미 | 별도 주효과 없음 | 3개 국가 더미 추가 |
| 목적 | 기존 40개 제품군 내 새 리뷰 | 학습에서 보지 못한 제품 |
| 모델 | XGBoost | 동일 XGBoost |
| 하이퍼파라미터 | Train CV로 확정 | 동일 값 재사용 |
| 역할 | 메인 성능 평가 | 추가 강건성 검증 |

실제 성능은

- 메인 Test F1: **0.819**
- Group Holdout 평균 F1: **0.794 ± 0.035**
- 메인 Test MCC: **0.438**
- Group Holdout 평균 MCC: **0.370 ± 0.040**
- 메인 Test ROC-AUC: **0.813**
- Group Holdout 평균 ROC-AUC: **0.767 ± 0.025**

로 나타났다.

그러나 두 분석은 분할 단위와 입력 변수 구성이 다르므로
단순한 점수 차이만 보고

> “Group Test가 더 높으므로 신제품에서 더 잘 맞는다”
> 

또는

> “Group Test가 낮으므로 메인 모델이 실패했다”
> 

고 해석하지 않는다.

Group 검증의 목적은

> **제품 고유 정보를 사용하지 않은 상황에서도 제품 속성과 국가별 패턴을 이용한 분류 성능이 어느 정도 유지되는지를 확인하는 것**
> 

이다.

# 23. 📌 머신러닝과 로지스틱 회귀의 연결

두 분석은 서로 대체 관계가 아니라

서로 다른 질문에 답한다.

## 로지스틱 회귀

```
어떤 속성이 만족도와 관련되는가?
↓
국가에 따라 그 효과가 달라지는가?
↓
p-value / Odds Ratio
```

## 머신러닝

```
이 변수들로 만족·불만족을 얼마나 잘 구분할 수 있는가?
↓
어떤 변수가 실제 예측에 많이 기여하는가?
↓
CV / Test / Feature Importance / SHAP
```

따라서

> **로지스틱 회귀로 통계적 효과를 검증하고,
머신러닝으로 예측 가능성과 변수의 예측 기여도를 추가 검증하였다.**
> 

---

# 24. 🔄 전체 머신러닝 분석 흐름

```
최종 분석 데이터 6,756건
↓
Y = 만족 / 불만족
↓
제품_ID 생성
↓
9개 속성
+
국가×속성 27개
+
제품_ID
= 원본 입력변수 37개
↓
Train 4,729건 / Test 2,027건
↓
Train 내부 5-Fold CV
↓
11개 분류 모델 베이스라인 비교
↓
8개 후보 Train 내부 GridSearchCV
↓
CatBoost와 XGBoost 성능 차이 검토
↓
CatBoost 제외 후 CV F1 1위 XGBoost 선택
↓
```

# ✅ 최종 정리

머신러닝 분석에서는 통계 분석에서 도출한

9개 제품 속성과 국가×속성 상호작용을 이용하여

소비자 만족·불만족을 분류하였다.

제품별 고유한 차이는 `제품_ID`를 명목형 변수로 추가하여 통제하였다.

모델 비교와 하이퍼파라미터 튜닝은 Train 내부 5-Fold CV에서 수행하였다.
튜닝 결과 CatBoost의 CV F1이 0.8251, XGBoost가 0.8238로
차이가 약 0.0013에 불과하였다.

이에 유사한 F1 성능에서 ROC-AUC, fold 간 변동성,
실행 환경의 계산 효율성을 함께 고려하여 CatBoost를 최종 선택 대상에서 제외하였고,
나머지 후보 중 CV F1이 가장 높은 **XGBoost**를 최종 모델로 선택하였다.

최종 XGBoost는 Test에서

- Accuracy **0.753**
- F1(만족) **0.819**
- F1(불만족) **0.614**
- Macro-F1 **0.716**
- MCC **0.438**
- ROC-AUC **0.813**

을 보였다.

모든 리뷰를 만족으로 예측하는 기준선의 Macro-F1은 0.395,
MCC는 0이었으므로 최종 모델은 단순한 다수 클래스 예측보다
만족·불만족을 더 잘 구분하는 것으로 확인되었다.

또한 Feature Importance와 XGBoost Native TreeSHAP을 통해
최종 모델이 만족·불만족을 구분할 때
어떤 제품 속성과 국가별 패턴을 활용하는지 확인하였다.

Global SHAP에서는 `자극`, `제품_ID`, `기능`, `보습`, `배송` 등이
상위 예측 기여 변수로 나타났으며,
`제품_ID`는 One-Hot 더미별 SHAP을 관측치 단위로 합산한 뒤
원본 변수 하나로 통합하여 해석하였다.

마지막으로 동일 제품이 Train과 Test에 동시에 포함되는
리뷰 단위 분할의 해석 범위를 보완하기 위해
제품 단위 반복 Group Holdout을 20회 수행하였다.

Group 검증에서는 제품_ID를 예측 정보에서 제외하고
메인 분석에서 선정된 동일한 XGBoost와 동일한 하이퍼파라미터를 사용하였다.

그 결과 처음 보는 제품에 대한 반복 검증에서
평균 F1 **0.794 ± 0.035**, MCC **0.370 ± 0.040**,
ROC-AUC **0.767 ± 0.025**가 확인되었다.

따라서 본 머신러닝 분석은

> **메인 분석을 통해 선정된 제품군 내 새로운 리뷰에 대한 예측 성능을 평가하고,
추가 Group Holdout을 통해 새로운 제품 수준의 일반화 가능성을 보조적으로 검증하는 이중 구조**
> 

로 구성하였다.

# ⚠️ 한계점 및 해석 범위

본 머신러닝 분석은 한국·미국·일본·러시아에서 선정한 40개 제품의 리뷰를 기반으로 수행되었으므로,
분석 결과를 전체 스킨케어 시장이나 모든 신제품에 일반화하는 데에는 한계가 있다.

메인 Test는 리뷰 단위 분할을 적용하였기 때문에 동일 제품의 서로 다른 리뷰가
Train과 Test에 함께 포함될 수 있다. 따라서 해당 성능은
**분석 대상 제품군 내 새로운 리뷰에 대한 일반화 성능**으로 해석하였다.
이를 보완하기 위해 제품 단위 반복 Group Holdout 검증을 추가하여,
학습에서 보지 못한 제품에 대한 일반화 가능성을 별도로 확인하였다.

Group Holdout에서는 메인 모델과 동일한 XGBoost 및 동일한 하이퍼파라미터를 유지하고
`제품_ID`를 예측변수에서 제외하였다. 대신 국가 정보의 주효과가 완전히 사라지지 않도록
한국을 기준으로 한 3개 국가 더미를 추가하였다.
따라서 메인 Test와 Group Holdout은 분할 단위뿐 아니라 입력 변수 구성도 일부 다르므로
점수의 단순 직접 비교에는 주의가 필요하다.

또한 만족·불만족 클래스의 비율이 완전히 동일하지 않으므로
Accuracy나 만족 클래스 F1 하나만으로 성능을 판단하지 않고
F1(불만족), Macro-F1, MCC, ROC-AUC 등을 함께 확인하였다.

Feature Importance와 SHAP은 모델이 예측 과정에서 어떤 변수를 활용했는지를 설명하는 도구이며,
통계적 유의성이나 인과관계를 의미하지 않는다.
따라서 통계적 효과는 로지스틱 회귀 결과를 중심으로 해석하고,
머신러닝 결과는 예측적 중요도와 패턴 확인을 위한 보조 근거로 활용하였다.

SHAP은 실행 환경의 보안 정책 때문에 Python `shap` 패키지 대신
XGBoost Native TreeSHAP으로 계산하였다.
`pred_contribs=True`의 additivity 검증 최대 오차는 2.62×10⁻⁶으로 확인되었다.

마지막으로 SHAP 분석은 계산 효율을 위해 Test 데이터 중 200건을 표본으로 사용하였으므로,
세부 중요도 순위와 개별 패턴에는 표본 변동 가능성이 존재한다.

**따라서 본 연구는 절대적인 예측모델 성능 제시보다는,
